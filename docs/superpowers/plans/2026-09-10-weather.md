# Desktop Widgets: Weather + ASCII weather effect — Implementation Plan

**Spec:** `docs/superpowers/specs/2026-09-10-round2-design.md` §3.

**Architecture:** `bin/dw-weather` (stdlib; Open-Meteo geocoder + forecast, per-place geo cache forever, forecast cache for `--max-age-min`, stale fallback) → `widgets/WeatherWidget.qml`. `widgets/Weather.js` is the pure effect engine (effect table by WMO group, deterministic RNG, particle field + cloud sprites, storm flash) drawn by `widgets/WeatherEffect.qml` in a second full-screen window the service adds to `placements` for any weather widget with `effect: true` (`back` → z −1e9, `front` → +1e9, `custom` → widget z). Because the shell's Variants reuses windows and appends new ones, the service now bumps a `gen` on every placement when `Registry.needsRebuild(oldKeys, newKeys)` says the order changed, so z edits and back/front changes re-stack live.
