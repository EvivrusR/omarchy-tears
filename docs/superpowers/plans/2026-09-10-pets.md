# Desktop Widgets: Pet widget — Implementation Plan

**Spec:** `docs/superpowers/specs/2026-09-10-pet-widget-design.md`. Michael's decisions (2026-09-10): reuse the Hermes/petdex sprite contract; first signals = Claude session %, battery, active agents **plus cpu / mem / gpu**; several pets at once, each watching something different; link the pet resources from the panel; size must be variable; first sheet = a `jill-stingray` sheet (kept local — petdex sprite, unclear licence), repo example = `hermes-girl` (hatched from Michael's own reference).

**Architecture:** `bin/dw-signals` (stdlib; reuses `dw-sample`) prints one flat JSON of signals. `widgets/Pet.js` is the pure rule engine: safe expression evaluator, `WATCH` presets (one ready-made rule set per thing to watch), edge detection for `on` rules, timed beats, Hermes' state names → sheet rows (9-row Codex or 8-row legacy). `widgets/PetWidget.qml` trims each row's blank trailing cells once via a hidden Canvas (Hermes' rule: max alpha ≤ 8 = padding), then drives a Qt `AnimatedSprite` — no per-frame JS. A `pet` widget = one pet; add as many as you like.
